# XGPS160 Bluetooth GPS trial — 2026-11-19

Procedure: `docs/hardware/gps-xgps160-trial.md`. MAC and positions are
deliberately omitted.

- Receiver: Dual XGPS160 (SkyPro), advertised as `XGPS160-xxxxxx`
- Pi: Raspberry Pi 5 Model B Rev 1.1, Raspberry Pi OS (Debian 13 trixie), BlueZ, gpsd 3.25
- Location: indoors at home, near a window, receiver on its own battery
- Home Assistant's Bluetooth integration was **not** loaded (removed, Decision #27)

## Results

| Step / test | Result | Notes |
|---|---|---|
| 1. Pair + trust | PASS | `bluetoothctl --agent NoInputNoOutput pair` succeeded; `info` then shows `Paired: no, Bonded: no, Trusted: yes`. The receiver doesn't keep a link key, which doesn't matter for SPP. |
| 1. Serial Port UUID | PASS | `00001101-…` listed, plus a vendor UUID. The kernel bug #217663 symptom did **not** occur. |
| 2. SPP channel | PASS | `sdptool browse` worked (no compat mode needed): **channel 1** |
| 3. Raw NMEA | PASS | `$GPGGA`/`$GPGSA`/`$GNGSA`/`$GPGSV`/`$GLGSV` plus a vendor `$GPPWR`. GPS + GLONASS, 13 satellites, HDOP 0.76, GGA fix quality 2 (SBAS). |
| 4. gpsd fix | PASS **with `-b`** | Default mode: `gpsd_flush: Input/output error`, `tcdrain() failed`, no data to clients. With `-b -n`: TPV mode 3, non-zero lat/lon, eph ≈ 2.9 m, **10 Hz**, zero errors. |
| 5a. Pi reboot | PASS | Permanent setup via bootstrap `gps_host`. After `systemctl reboot`, with no manual steps: `rfcomm-gps` active, gpsd running `-b -n`, rfcomm connected by itself, **3D fix at 34 s uptime** (eph ≈ 2.85 m), all four containers up, `throttled=0x0`. |
| 5b. Receiver power cycle | PASS | Data stopped when switched off and resumed automatically when switched on, straight back to a 3D fix. 77 s total gap, including off time. gpsd logged nothing; rfcomm reconnected by itself. |
| 5c. Coexistence with HA BLE scanning | deferred to M3 | HA Bluetooth not loaded until Victron |
| 5d. 24 h on USB power in the van | open | |
| 5e. chrony with gpsd SHM refclock | open | issue #22 |
| 5f. Drive | open | |
